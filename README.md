# 台词提示单（Line Cue Sheet）

供小剧团排练使用的 **台词提示单 Web 应用**：粘贴分场剧本文本，在任意台词旁挂接
**灯光（💡）/ 音效（🔊）提示**；剧本修改后保存为新版时，系统依据**台词文本及相邻行上下文**
自动重新定位所有提示。遇到重复台词、台词被删除等无法唯一确认的情况，会标记为
**待确认**并给出候选行 —— **绝不会悄悄挂到另一句相同台词上**，须由人工重新绑定后保存。

内置**本机音效素材库**：上传 MP3 / WAV / OGG 音频（单个不超过 10 MB），按文件内容
SHA-256 去重，音效提示可关联、替换、解除素材并在剧本详情页直接试听；**创建排练场次时素材被一并
冻结进快照**，提示后来改绑/解除素材，旧场次仍播放原素材。

另附**跨剧本共用的道具借还台账**：登记道具名称与正整数总量，在剧本详情页借出给领用人、
按借用记录分批归还；借还请求携带台账版本，服务端在同一事务内校验版本与数量并递增版本，
**超额借出、超额归还或版本过期一律返回 409 且台账不变**。

技术栈：Node.js + Express + 原生前端（HTML/CSS/JS，无构建）+ SQLite（better-sqlite3）。

---

## 一条命令启动（Docker Compose）

```bash
docker compose up --build -d
```

该命令会一次性完成：

1. 构建镜像并安装全部依赖（含 better-sqlite3 原生模块编译）；
2. 容器启动时自动初始化 SQLite 数据库（`server/init-db.js` 自动建表，无需手工操作）；
3. 启动 Web 服务。

启动后访问：

> **http://localhost:8080**

停止：`docker compose down`（数据保留在命名卷 `cue-data` 中——包括数据库与音效素材文件，
删除数据可用 `docker compose down -v`）。

---

## 必要配置（可选，均有默认值）

通过环境变量 / `.env` 文件配置（见 `docker-compose.yml`）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT`（宿主机映射） | `8080` | 宿主机访问端口。修改后访问 `http://localhost:<端口>`（容器内固定监听 3000） |
| `DB_PATH`（容器内） | `/app/data/cues.db` | SQLite 数据库文件路径，位于持久化卷 `/app/data` 内 |
| `ASSET_DIR`（容器内） | `/app/data/assets` | 音效素材文件目录，默认与数据库同处 `cue-data` 卷内，随卷持久化 |

示例：改用宿主机 8080 端口——

```bash
echo "PORT=8080" > .env
docker compose up --build -d
# 访问 http://localhost:8080
```

## 本地开发（不使用 Docker）

要求 Node.js 20+（better-sqlite3 安装时需要网络；如本地无预编译包则需 python3 / make / g++）。

```bash
npm install          # 安装依赖
npm run init-db      # 初始化数据库（默认 ./data/cues.db，可被 DB_PATH 覆盖）
npm start            # 启动，访问 http://localhost:3000
```

## 使用说明

1. **创建剧本**：首页输入标题，粘贴分场剧本文本（每行一句台词/舞台提示，空行会保留以维持行号）。
2. **添加提示**：打开剧本，点击任意一句台词，在弹窗中选择「💡 灯光 / 🔊 音效」并填写内容与备注。
   保存时系统会记录该句锚点台词及其**前后各 2 行非空文本**作为上下文快照。
3. **查看提示单**：右侧按行号列出全部提示，点击台词可滚动定位到剧本对应行。
4. **编辑剧本（保存新版）**：点击「编辑剧本（保存新版）」修改文本后保存，系统自动：
   - 生成新版本快照（可在数据中追溯，当前版本号显示在标题旁）；
   - 对每条提示在新版中全文重新定位：

     | 定位结果 | 处理方式 |
     | --- | --- |
     | 全文唯一匹配 | 自动绑定 |
     | 多处相同台词，且相邻上下文可区分出唯一位置 | 自动绑定 |
     | 多处相同台词、上下文打平无法区分 | **待确认（重复）**，列出候选行 |
     | 只剩一处相同台词，但相邻上下文与原快照完全不符（可能是重复句之一被删） | **待确认（重复）**，列出该候选供确认 |
     | 全文找不到该台词（被删除/改写） | **待确认（缺失）** |
5. **人工重新绑定**：待确认提示集中展示在右侧红框面板，可
   - 一键绑定到系统给出的候选行；
   - 或点「点选台词重绑…」在完整剧本中点击正确的台词行。

   绑定后锚点与上下文快照同步更新，状态恢复为已绑定。
6. 提示内容随时可编辑、删除；剧本可改名、删除（级联删除其版本与提示）。
7. **排练执行台**：详情页切换到「🗂️ 排练执行台」标签，可从剧本**当前版本**冻结生成排练场次，
   供舞台监督排练时逐条执行灯光/音效提示：
   - **创建即冻结**：场次保存创建时刻每条已绑定提示的**行号、类型、内容、备注**（及锚点台词）；
     **音效提示同时冻结当时关联的素材**（素材 ID 与文件名一并写入冻结条目，`session_items.asset_id` /
     `asset_filename`），按**行号、提示 ID** 排序；**待确认提示无法执行，会被排除并在创建前显示排除数量**。
     没有任何可执行提示时**不会创建空场次**（接口返回 409，按钮禁用）。
     场次详情中音效条目显示冻结的**素材文件名并可直接试听**：即使提示后来**改绑、解除或删除**了素材关联，
     旧场次播放的仍是创建时冻结的**原素材**；**旧场次没有素材快照时显示「未关联素材」**。
   - **逐条执行**：一次只能执行**队首**一条并记录执行时间；提交时需带上目标条目 ID 与
     **预期进度**做乐观锁校验——重复提交、越序跳过、基于过期进度的请求一律返回 **409 冲突**，
     不会推进下一条。
   - **漏执行登记**：队首提示无法按计划执行时，点「⚠ 登记漏执行」填写**原因**并确认，
     该条被标记为**漏执行**并继续处理下一条。漏执行与正常执行**共用同一进度与预期进度校验**，
     重复提交、越序或过期请求同样返回 **409**；原因随场次记录保存，在队列与执行记录中展示。
   - **撤回**：仅可撤回**最后处理的一条**（正常执行或漏执行），撤回后该条回到待处理、可重新执行或重新登记；
     该条处理时记录的**有效排练秒数时间点随记录一并移除**（冻结队列顺序始终不变；计时累计不回滚，
     撤回前若已完成并自动停表，撤回后场次回到未完成、计时保持暂停，可再点「继续」）。
   - **操作轨迹（只读时间线）**：**执行、登记漏执行、撤回队尾成功**时，与原操作在**同一事务**中向
     `session_events` 追加一条**不可修改**的事件（应用层不提供任何修改/删除入口，仅随场次级联删除）：
     - 事件按**场次内递增序号**（`seq`，只增不重用）记录**服务端时间**、**冻结条目**、
       **处理类型**（执行 / 漏执行 / 撤回）及**漏执行原因**，并快照发生时刻的有效排练秒数；
     - **撤回事件关联被撤回的那次处理事件**（`undoes_event_id`），并冗余其类型与原因；
       同一条目撤回后**重新处理会生成全新事件**，旧事件保留、在时间线上标注「已被 #N 撤回」；
     - **冲突或过期请求不留事件**：所有校验失败（409）都发生在插入事件之前，整笔事务回滚；
     - **旧场次不补造**：轨迹功能启用前的处理记录不会补造事件（时间线可能为空或从中间开始），
       撤回这类旧记录时仍会留下撤回事件（无对应事件可关联，标注「轨迹启用前的记录」）；
     - 场次详情底部的「操作轨迹」区块即该时间线的只读展示，与「执行记录」（当前有效处理，
       撤回即移除）并列，可对照看出哪次处理已被撤回。
   - **有效排练计时**：每个场次有独立的服务端计时，点击「▶ 开始计时 / ⏸ 暂停 / ▶ 继续」即可：
     - 计时状态（未开始 / 计时中 / 已暂停）、**累计有效秒数**与**状态版本**全部由服务端持久化；
       有效时长一律**按服务端时间**计算（暂停期间不走表），因此**刷新页面、关闭浏览器甚至服务重启后**
       再打开，当前状态与有效时长都能准确恢复，多个浏览器打开同一场也保持一致。
     - 切换请求带**预期状态版本**做乐观锁校验：重复点击、或基于旧版本的切换（例如另一浏览器已暂停）
       一律返回 **409 冲突**，每一段时间只在暂停（或完成自动停表）时结算一次，**不能重复累计**。
     - **执行或登记漏执行时，在同一事务内记录该条对应的有效排练秒数**，显示在队列条目与执行记录中
       （格式 `M:SS` / `H:MM:SS`）；**从未开始计时的场次可照常执行**，这些记录显示 **「未计时」**。
     - 全部条目处理完时服务端在同一事务内**自动停表**，之后不能再切换计时；页面头部与历次场次列表
       都会显示当前/最终有效时长，计时中数字每秒自动跳动。
   - **刷新恢复**：进度、处理记录与有效排练计时全部存在服务端，刷新页面后重新打开场次即恢复。
   - **快照不可变**：剧本改版或提示后续被编辑/删除（含音效提示**改绑、解除、删除素材关联**），
     **均不改变既有场次**——场次永远播放创建时冻结的原素材，可随时在右侧「历次场次」中查看每一场的
     冻结快照与执行记录（旧场次无素材快照时音效条目显示「未关联素材」）。
   - **完成判定**：全部条目处理完（已执行 + 漏执行 = 总数）即标记**已完成**；
     场次详情与历次场次均分开统计**已执行 / 漏执行**数量。
8. **场次条目修订建议**：排练中发现提示文案需要调整时，不必当场改动剧本提示——
   在执行台点击队列条目的「✏️ 建议」，为**冻结条目**填写新的提示内容和备注：
   - 建议保存在**场次下**（`session_item_suggestions`），刷新页面后仍可查看、修改或删除；
     修改建议会将其重置为**待处理**状态。
   - **采纳**时系统在同一事务内核对：① 来源提示仍存在；② 剧本当前版本与场次冻结版本一致、
     且提示仍绑定在快照行；③ 提示的**类型、内容、备注**与该条目快照完全一致。
     任一条件不符即返回 **409 冲突**，建议被**保留**并标记为**冲突**（附原因），
     **绝不覆盖排练后对提示的编辑**；待处理与冲突状态都会展示在执行台与历次场次列表中。
   - 核对全部通过才把建议的内容/备注写回**当前提示**并标记建议**已采纳**；
     场次的冻结条目快照与执行记录始终保持原样，已采纳的建议作为历史保留，不可再改。
9. **场次对照**：在「🗂️ 排练执行台」标签底部的「🔀 场次对照」面板，从历次场次中任选
   **基准场**与**对照场**（默认基准场 = 最新一场、对照场 = 次新一场），点击「对照」：
   - **按来源提示 ID 对齐**：以冻结条目记录的来源提示 ID（`session_items.cue_id`）配对两场，
     **绝不按队列序号或台词文本配对**——即使中途删除/新增提示导致序号错位，也不会对错。
   - 分别列出**只在基准场出现**与**只在对照场出现（新增）**的提示；共同提示并排展示两场的
     **行号、类型、内容、备注**及**已执行 / 漏执行 / 待处理**状态，有变化的字段高亮并标注变化项。
   - **未变化的共同提示默认折叠**（可逐条展开，或勾选「展开未变化项」全部展开）。
   - 展示顺序：共同提示与基准场独有提示按**基准场队列顺序**排列；对照场独有（新增）提示
     **接在末尾并保持其在对照场中的顺序**。
   - 对照为**只读视图**：历史场次与当前提示均不会被改写。
   - 访问入口与端口：启动后进入 **http://localhost:8080** → 打开剧本 →
     「🗂️ 排练执行台」标签 → 页面底部「🔀 场次对照」（端口随 `PORT` 环境变量变化，见上文配置）。
10. **漏项补排**：任意场次（包括补排场自身）登记过漏执行后，执行台场次详情中会出现
    **「🔁 漏项补排」入口**，可从某场次**当前尚未补排**的漏执行记录**一键生成补排场次**：
    - **按原队列顺序冻结**：补排场条目沿用来源队列顺序（原处理顺序）逐条冻结提示的
      **行号、类型、文案、备注**以及该条的**漏执行原因**，**素材快照同样沿用来源冻结条目**
      （`session_items.asset_id` / `asset_filename`，创建补排场时**不再回查当前提示**的关联——
      即使提示已改绑/解除素材，补排场仍播放来源条目当时的原素材），并同时记下来源场次、原冻结条目与
      原处理记录（`session_makeup_sources`）。
    - **事务内复核**：创建请求在同一事务内重新确认每条来源记录**仍为漏执行、且尚未进入任何补排场**；
      来源场次在预览后**撤回**了该漏执行再提交（过期请求）、或记录已被别的补排场使用，一律返回 **409 冲突**；
      数据库以 `UNIQUE(source_execution_id)` 兜底，保证**同一条漏执行记录只能进入一个补排场次**。
      没有可冻结条目时拒绝创建，**不会生成空场次**（409）。
    - **补排场即普通场次**：生成后沿用现有**逐条执行、漏执行登记、撤回、修订建议**等全部操作与乐观锁校验；
      场次详情头部标注「🔁 漏项补排场」并展示**来源场次（可点击跳回）与冻结的原漏执行原因**，
      队列中每条标注「补排自原 #序号」及原原因；**原场次的冻结条目、执行记录及剧本当前提示均保持原样、不被改动**。
    - 来源场次列表会显示漏执行总数、已补排数与待补排数；撤回后漏执行记录消失即不再可补排，
      已生成的补排场不受来源撤回影响（来源信息为创建时冻结）。
    - 访问入口：**http://localhost:8080** → 打开剧本 → 「🗂️ 排练执行台」→
      打开任一场次 → 详情中的「🔁 漏项补排」面板（容器内服务仍监听 3000，仅宿主机默认映射 8080；本地 `npm start` 仍为 3000）。
11. **剧本版本回溯**：详情页切换到「🕘 版本回溯」标签，可查看与恢复任意历史版本：
    - **版本列表 + 正文只读查看**：左侧按版本号倒序列出 `script_versions` 的**版本号与保存时间**
      （并标注当前版本、显示该版行数），点开任一版本即在右侧查看**该版全文快照**，快照始终只读、不可变。
    - **先预览、后恢复**：对任一非当前版本点「预览提示迁移结果」，系统按**现有重定位规则**
      （与保存新版完全相同的规范化匹配 + 上下文打分，只读演算、不改数据）给出把当前提示迁移到该正文后的
      **已绑定数量 / 待确认数量**，并逐条列出待确认提示的原因与候选行。
    - **恢复 = 另存递增新版本**：确认恢复后，该历史正文会被**保存为一个递增的新版本**
      （当前版本与全部历史快照原样保留，绝不覆盖或删除）；同一事务内按现有规则更新全部提示——
      **重复台词无法唯一定位时保持待确认并给出候选行**，绝不会静默挂到另一句相同台词上。
    - **乐观锁防并发覆盖（剧本版本 + 提示集合双凭据）**：恢复预览响应除携带**预览时的当前版本号**
      （`current_version`）外，还携带一个覆盖**提示集合及迁移相关状态**（锚点台词、相邻上下文、
      绑定状态等）的校验凭据 `cue_token`；确认恢复时前端把两者（`expectedCurrentVersion`、
      `expectedCueToken`）**原样提交**，服务端在**同一恢复事务内同时复核**：
      另一窗口在此期间已改版（版本号不一致），或在**不改变版本号**的情况下对同一剧本的提示
      **新增、删除、改绑或修改**（凭据不一致），任一过期均返回 **409 冲突**，
      **不生成新版本、也不改动任何提示**（整笔事务回滚）。
    - **冲突后的操作**：页面收到 409 后会自动同步为服务端最新状态并**清除旧预览**，
      恢复面板回到「预览提示迁移结果」——确认按钮不再可用，需**重新预览**（按现有重定位规则
      重新演算）后才能再次确认恢复，保证实际迁移与所确认的预览一致。
    - 访问入口（本机）：**http://localhost:8080**（Docker Compose 默认把容器内 3000 端口映射到
      宿主机 **8080**；用 `PORT=<端口> docker compose up` 可改宿主机端口，访问
      `http://localhost:<端口>`；本地直接 `npm start` 则访问 **http://localhost:3000**）
      → 打开剧本 →「🕘 版本回溯」标签。
12. **音效素材库**：详情页切换到「🔊 音效素材库」标签，管理本机共享的音频素材：
    - **上传**：选择 MP3 / WAV / OGG 文件（单个不超过 **10 MB**）；服务端校验文件头魔数
      （扩展名必须与真实格式一致），并按文件内容 **SHA-256 去重**——同一内容重复上传
      （即使文件名不同）会**复用原素材记录与文件**，不产生新记录；
    - **关联与试听**：添加/编辑**音效提示**时可在弹窗中下拉选择素材（选择、替换或选
      「不关联素材」解除）；保存后提示单中的音效提示会显示 🎵 素材名与「▶ 试听」按钮，
      素材库列表与选择弹窗中也可随时试听；灯光提示不能关联素材（改为灯光类型会自动解除）；
    - **删除保护**：删除素材前服务端**同时检查当前提示与各场次冻结条目（含补排场）的引用**，
      **任一方仍引用即返回 409 冲突**——响应附分项引用数量（`cue_ref_count` / `frozen_ref_count`）
      与可定位的引用明细：当前提示给出「剧本 / 提示」，冻结条目给出「剧本 / 场次（标注补排场）/ 队列序号」，
      前端据此提示解除提示关联或删除对应旧场次所在剧本；双方均无引用才删除，记录与文件一并清理。
      **删除剧本时其全部场次（冻结条目）级联清除，素材的冻结引用随之消失**；
    - **失败不留痕**：上传任一环节失败（格式不符、超限、写盘错误等）都不会留下可见记录
      或残缺文件（临时文件 + 原子重命名，服务启动时还会兜底清理孤儿文件）；
    - **持久化**：素材文件保存在 `ASSET_DIR`（默认 `/app/data/assets`）并随 `cue-data`
      数据卷持久化，关联关系保存在 SQLite 中，容器重建后完好；
    - 访问入口：**http://localhost:8080** → 打开剧本 →「🔊 音效素材库」标签。
13. **道具借还**：详情页切换到「🧰 道具借还」标签，管理**跨剧本共用**的道具库存台账：
    - **登记道具**：填写道具名称与**正整数总量**（名称唯一，重复登记返回 `409`）；道具库为
      全剧目共用，在任一剧本的该标签页看到的都是同一份台账。
    - **借出**：在道具卡片上填写**领用人**与**正整数数量**，借出记录登记在**当前打开的剧本**名下；
      每种道具展示**总量、未归还合计与可借量**（可借量 = 总量 − 全部剧本未归还数量合计）。
    - **归还**：按**借用记录**分批归还——每条未归还记录自带归还表单（默认填入该记录全部未还数量，
      可改小分批归还），归还只抵扣**所选记录**，不影响同道具的其他记录；**全部归还后记录保留**
      在台账中（展示在「已归还记录」区，只读）。
    - **各剧本未归还记录**：每种道具列出**所有剧本**尚未归还的借用记录（当前剧本的排在前面并标注
      「本剧本」），含领用人、借出 / 已还 / 未还数量与借出时间。
    - **乐观锁（409）**：借出与归还请求都携带页面读取的**台账版本**（`expectedVersion`），服务端在
      **同一事务**内校验版本与数量、更新借用记录并递增版本；**超额借出、超额归还或版本过期**
      （另一窗口已借还）一律返回 **409 且台账不变**，页面提示刷新后重新操作（并自动刷新为最新台账）。
    - **持久化**：台账与借用记录保存在 SQLite（`props` / `prop_loans` 表，随服务启动自动建表），
      刷新页面或服务重启后数据仍在；删除剧本时其借用记录级联清除，占用的库存随之释放。
    - 访问入口：**http://localhost:8080** → 打开剧本 →「🧰 道具借还」标签
      （容器内服务监听 3000，仅宿主机默认映射 8080；本地 `npm start` 访问 3000）。

## 数据模型

- `scripts`：剧本（当前版本号、当前正文）
- `script_versions`：每次保存新版的全文快照
- `cues`：提示（类型、内容；锚点行号/文本、前后上下文快照；`bound` / `pending` 状态及待确认原因与候选行）；
  `asset_id` 为音效提示关联的素材（可空，灯光提示恒为 NULL），引用 `sound_assets(id)`
- `sound_assets`：音效素材库（本机全剧目共用）。`sha256` 为文件内容摘要（UNIQUE，去重键），
  `filename` 为首次上传时的原始文件名，`ext` 限 `.mp3` / `.wav` / `.ogg`，`size` 为字节数，
  `stored_name` 为磁盘文件名（`<sha256><扩展名>`，存于 `ASSET_DIR`）；
  **被任何当前提示或场次冻结条目引用时禁止删除**（引用计数分项为 `cue_ref_count` / `frozen_ref_count`）
- `sessions`：排练场次（创建自哪个剧本版本、名称、条目总数、被排除的待确认提示数；
  `kind` 区分普通场 `normal` / 漏项补排场 `makeup`，补排场以 `source_session_id` 记来源场次）；
  有效排练计时四列 `timer_state`（`idle`/`running`/`paused`）、`timer_elapsed`（已落账累计有效秒）、
  `timer_started_at`（当前计时段开始的服务端 epoch 秒，仅 running 非空）、`timer_version`（状态版本，乐观锁）
- `session_items`：场次冻结条目（序号、来源提示 ID、行号、类型、内容、备注、锚点台词文本）；
  **`asset_id` / `asset_filename` 为创建时刻关联素材的冻结快照**：普通场次取自当时的当前提示，
  补排场沿用来源冻结条目（均不随后续提示改绑/解除/删除而变化，旧场次无快照时为 NULL / ''，
  页面音效条目显示「未关联素材」）。`cue_id` 不与 `cues` 建外键，提示日后被编辑或删除不影响旧场次；
  `asset_id` 以普通 `REFERENCES sound_assets(id)` 引用素材（无级联），只要仍被冻结条目引用素材就无法删除
- `session_executions`：处理记录（条目、顺序号、处理时间；`kind` 区分 `done` 正常执行 / `missed` 漏执行，
  漏执行在 `miss_reason` 记录原因；`rehearsal_seconds` 记该条处理时刻的有效排练秒数，NULL=处理时从未计时
  即页面上的「未计时」，撤回删除记录时该时间点一并移除），`(场次, 条目)` 唯一，防止重复处理；正常执行与漏执行共用同一进度序列
- `session_events`：场次操作轨迹（只增不改的审计事件）。执行 / 登记漏执行 / 撤回队尾成功时与原操作
  同一事务追加；`seq` 为场次内递增序号（`(场次, 序号)` 唯一），`kind` 为 `done` / `missed` / `undo`，
  记录服务端时间 `created_at`、冻结条目 `item_id`、漏执行原因与发生时刻的有效排练秒数；
  `undo` 事件以 `undoes_event_id` 关联被撤回的那次处理事件（并冗余 `undone_kind` 与原因，
  轨迹启用前的旧记录无事件可关联时为 NULL）；`done` / `missed` 事件以 `execution_id` 记对应处理记录
  （撤回删除后仅作追溯，不建外键）。同一条目重新处理生成新事件；冲突/过期请求随事务回滚不留事件；
  旧场次启用前的操作不补造。无修改/删除入口，仅随场次级联删除
- `session_makeup_sources`：漏项补排来源（补排场每条冻结条目的来源场次、原条目、原漏执行处理记录、
  原处理序号与冻结的行号/类型/文案/备注/漏执行原因，**以及 `original_asset_id` /
  `original_asset_filename` 来源素材快照**）；`UNIQUE(source_execution_id)` 保证同一条漏执行记录
  只能进入一个补排场次；来源撤回/删除不影响已冻结的补排场。素材引用计数/删除冲突以新场次
  `session_items` 的快照为准（避免同一条漏执行被重复计数）
- `session_item_suggestions`：场次条目修订建议（建议的新内容/备注；`pending` / `adopted` / `conflict`
  状态及冲突原因），挂在场次与条目下，随场次级联删除；采纳时事务内核对来源提示与快照一致才回写 `cues`
- `props`：道具库存台账（本机全剧目共用）。`name` 唯一，`total` 为正整数总量；
  `version` 为台账版本（乐观锁），每次借出 / 归还在同一事务内 +1
- `prop_loans`：道具借用记录（挂在借出时打开的剧本下，随剧本级联删除）。`borrower` 为领用人，
  `quantity` 为正整数借出数量，`returned` 为累计已归还数量（分批归还、只增不减，
  `returned = quantity` 即全部归还，**记录保留不删除**）；未归还数量 = `quantity - returned`，
  某种道具的可借量 = `total − 该道具全部记录未归还数量合计`

> 数据库随服务启动自动建表（`CREATE TABLE IF NOT EXISTS`）：旧版本创建的卷在升级后首次启动时
> 会自动补齐 `session_item_suggestions` 表、`session_executions` 的 `kind` / `miss_reason` /
> `rehearsal_seconds` 列（已有执行记录默认记为正常执行、有效排练秒数为空即显示「未计时」）以及
> `sessions` 的 `kind` / `source_session_id` 列、有效排练计时四列（`timer_state` / `timer_elapsed` /
> `timer_started_at` / `timer_version`，旧场次默认从未计时）、`session_makeup_sources` 表（漏项补排来源）、
> `session_events` 表（场次操作轨迹；**启用前的旧处理记录不补造事件**，此后新的执行/漏执行/撤回
> 才开始留痕）、`sound_assets` 表（音效素材库）与 `cues` 的 `asset_id` 列（既有提示均为 NULL 即未关联素材），
> 以及 `session_items` 的 `asset_id` / `asset_filename` 素材快照列与
> `session_makeup_sources` 的 `original_asset_id` / `original_asset_filename` 列
> （旧场次没有素材快照，音效条目显示「未关联素材」），以及 `props` / `prop_loans` 表
> （道具借还台账），无需手工迁移。

## 音效素材库 API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/assets` | 素材列表（含引用次数 `ref_count`，并分项给出当前提示引用 `cue_ref_count` 与场次冻结引用 `frozen_ref_count`） |
| `POST /api/assets?filename=<文件名>` | 上传素材：请求体为音频原始字节；仅 MP3 / WAV / OGG 且魔数与扩展名一致，单文件 ≤ 10 MB（超限 `413`）；按 SHA-256 去重，同内容重复上传返回原记录（`deduped: true`）；失败不留记录或残缺文件 |
| `GET /api/assets/:id/file` | 素材音频文件（按扩展名返回 `audio/*` Content-Type，支持 Range，供页面试听） |
| `DELETE /api/assets/:id` | 删除素材：**当前提示或场次冻结条目（含补排场）任一方仍引用时返回 `409`**（附 `ref_count`、分项 `cue_ref_count` / `frozen_ref_count` 与可定位明细 `cue_references`（剧本/提示）、`frozen_references`（剧本/场次/队列序号，补排场带 `session_kind='makeup'`））；双方均无引用才删除，记录与文件一并清理。删除剧本时场次级联清除，冻结引用随之消失 |

提示关联素材的字段：`POST /api/scripts/:id/cues` 与 `PATCH /api/cues/:cueId` 接受可选
`assetId`（仅音效提示有效；传 `null` 解除关联，不传保持不变；类型改为灯光自动解除）；
`GET /api/scripts/:id` 返回的每条提示带 `asset: { id, filename, size } | null`。

> **场次素材快照**：`POST /api/scripts/:id/sessions` 创建普通场次时把每条音效提示当时关联的素材
> （ID + 文件名）冻结进 `session_items`；`POST /api/sessions/:sessionId/makeup` 生成补排场时
> **直接沿用来源冻结条目的素材快照，不再查询当前提示**。`GET /api/sessions/:id` 每个条目、
> 每条处理记录、以及 `GET .../makeup-preview` 每条候选均带 `asset: { id, filename } | null`
> （旧场次无快照时音效条目为 `null`，页面显示「未关联素材」）；创建预览 `GET .../sessions/preview`
> 的每条 `cues` 同样带 `asset`。试听文件统一走 `GET /api/assets/:id/file`，只要仍被任一条目引用，
> 素材记录与文件就不会被删除。

## 排练场次 API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/scripts/:id/sessions/preview` | 创建前预览：当前版本、可执行条目数、待确认排除数 |
| `POST /api/scripts/:id/sessions` | 从当前版本创建场次（无可执行提示返回 `409`） |
| `GET /api/scripts/:id/sessions` | 历次场次列表（含已执行/漏执行进度摘要、当前/最终有效排练秒数 `rehearsal_seconds` 与待处理/冲突建议计数） |
| `GET /api/scripts/:id/sessions/compare?base=<场次ID>&compare=<场次ID>` | 同一剧本两场场次对照（只读）：按来源提示 ID 对齐，返回共同提示的行号/类型/内容/备注/状态差异、各自独有提示；共同项按基准场顺序，对照场新增项接末尾 |
| `GET /api/sessions/:sessionId` | 场次详情：冻结条目快照 + 处理记录（含漏执行原因与每条的有效排练秒数）+ 修订建议；含服务端计时状态 `timer_state` / `timer_elapsed` / `timer_started_at` / `timer_version`、当前有效秒 `rehearsal_seconds`（NULL 为从未计时）与服务端时间 `server_now`；补排场另带来源场次与每条的 `makeup_source`（原条目/原序号/原原因）；`events` 为**操作轨迹只读时间线**（按场次内递增 `seq` 排列的执行/漏执行/撤回事件，含服务端时间、冻结条目、漏执行原因与有效排练秒数快照；撤回事件带 `undoes_event_id` / `undoes_seq` 关联被撤回事件，被撤回的处理事件标 `undone` / `undone_by_seq`；旧场次启用前的操作不补造） |
| `POST /api/sessions/:sessionId/timer` | 切换有效排练计时，请求体 `{ action, expectedVersion }`，`action` 为 `start` / `pause` / `resume`；状态、累计秒数与状态版本由服务端持久化，重复或基于旧版本（含跨浏览器）的切换返回 `409`，不能重复累计；已完成场次返回 `409`。响应返回更新后的计时状态与 `server_now` |
| `GET /api/sessions/:sessionId/makeup-preview` | 漏项补排预览：漏执行总数、已补排数、当前尚未补排的漏执行记录（按原队列顺序，含冻结行号/类型/文案/备注/原因） |
| `POST /api/sessions/:sessionId/makeup` | 一键生成漏项补排场，请求体 `{ name? , sourceExecutionIds? }`（缺省补全部未补排项）；事务内复核来源仍为漏执行且未被补排，撤回后提交（过期）/重复补排返回 `409`，无条目不生成空场次 |
| `POST /api/sessions/:sessionId/execute` | 执行队首，请求体 `{ itemId, expectedProgress }`；同事务记录该条的有效排练秒数并追加 `done` 操作事件；过期/重复/越序返回 `409`（不留事件）；最后一条处理完同事务自动停表 |
| `POST /api/sessions/:sessionId/miss` | 登记漏执行，请求体 `{ itemId, expectedProgress, reason }`（原因必填）；同事务记录有效排练秒数并追加 `missed` 操作事件（含原因），与执行共用进度校验，过期/重复/越序返回 `409`（不留事件）；最后一条处理完同事务自动停表 |
| `POST /api/sessions/:sessionId/undo` | 撤回最后处理的一条（执行或漏执行），请求体 `{ expectedProgress }`；该条的有效排练秒数时间点随记录移除，队列顺序不变；同事务追加 `undo` 操作事件（关联被撤回的处理事件，并冗余其类型/原因），过期返回 `409`（不留事件） |
| `POST /api/sessions/:sessionId/items/:itemId/suggestions` | 为冻结条目提交修订建议，请求体 `{ label, note }` |
| `PATCH /api/suggestions/:suggestionId` | 修改建议内容/备注（仅未采纳；修改后重置为待处理） |
| `DELETE /api/suggestions/:suggestionId` | 删除建议（已采纳的作为历史保留，返回 `409`） |
| `POST /api/suggestions/:suggestionId/adopt` | 采纳建议：事务内核对来源提示存在、剧本版本与绑定行未变、类型/内容/备注与快照一致；不符则标记冲突并返回 `409`（建议保留），通过才写回当前提示并标记已采纳 |

## 剧本版本回溯 API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/scripts/:id/versions` | 版本列表：按版本号倒序返回各版本的版本号、标题、保存时间 `created_at`、行数与 `is_current`（不含正文） |
| `GET /api/scripts/:id/versions/:version` | 查看某一版本的全文快照（只读）；不存在的版本返回 `404`，当前版本响应 `is_current=true` |
| `GET /api/scripts/:id/versions/:version/restore-preview` | 恢复前预览（只读）：用与「保存新版」相同的重定位规则演算把当前提示迁移到该版正文，返回 `current_version`（预览时当前版本号，恢复须原样带回）、`cue_token`（覆盖提示集合及迁移相关状态的 SHA-256 凭据，恢复须原样带回）、`target_version`、`total` / `bound` / `pending` 数量及每条待确认提示的原因与候选行 `pending_cues`；目标为当前版本返回 `400` |
| `POST /api/scripts/:id/versions/:version/restore` | 确认恢复，请求体 `{ expectedCurrentVersion, expectedCueToken }`：事务内**同时**校验当前版本号与提示集合凭据，任一不符（另一窗口已改版，或对同一剧本的提示新增/删除/改绑/修改但版本号未变）返回 **`409`** 且**不生成新版本、不改提示**，要求重新预览；缺少/格式非法的凭据返回 `400`。通过则把该历史正文**另存为递增新版本**（原历史快照全部保留），并在同一事务按现有重定位规则更新提示，重复台词无法唯一定位时保持待确认并附候选行。响应含新版本号 `version`、来源版本 `restored_from` 与重定位统计 `stats` |

> 版本回溯复用既有的 `script_versions` 全文快照表，**无需数据库迁移**；历史快照始终不可变，
> 恢复操作只会新增一个版本快照，不会改写或删除任何旧版本。

## 道具借还 API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/props` | 道具台账列表（全剧目共用）：每种道具的 `name`、`total`（总量）、`borrowed`（全部剧本未归还合计）、`available`（可借量 = 总量 − 全部未归还）与台账版本 `version`；`loans` 为全部借用记录（含剧本名、领用人、借出 / 已还 / 未还数量；已还清的记录同样返回——全部归还后记录保留） |
| `POST /api/props` | 登记道具，请求体 `{ name, total }`：`total` 必须为正整数（否则 `400`）；名称重复返回 `409` |
| `POST /api/props/:id/borrow` | 在指定剧本下借出，请求体 `{ scriptId, borrower, quantity, expectedVersion }`：同一事务内校验台账版本与可借量、写入借用记录并递增版本；**版本过期或超额借出返回 `409` 且台账不变**；`quantity` 为正整数、`borrower` 必填（否则 `400`） |
| `POST /api/loans/:loanId/return` | 按所选借用记录分批归还，请求体 `{ quantity, expectedVersion }`：只抵扣该记录，同一事务内校验版本与该记录未归还数量、累计归还并递增版本；**版本过期或超额归还返回 `409` 且台账不变**；全部归还后记录保留（`returned = quantity`），不会删除 |
